# MuJoCo–MPM 深度双向耦合实施计划

- 日期：2026-10-19
- 状态：P0 首轮审计和 P1 小场景参考实现已落地；P2–P4 尚未实现
- 参考实现：本地 `FAST_MJVBDV2` 分支，提交 `2af3c8c0`
- 目标：参考 MJVBD v2 的所有权和执行架构，建立代码独立的 MuJoCo–MPM 求解器。MuJoCo 仅负责选中的关节系统及其连杆，其余自由刚体、软体和材料全部由私有 MPM 侧负责，并逐步实现同一步内协调、保留关节链响应的双向耦合。
- 本文件中 `SolverMJMPM` 为暂定名称；新增模式、接口与性能目标均为计划，不代表现有能力。

实施记录见 [P0/P1 报告](../lab/mjmpm/README.md) 和 [数值验证结果](../lab/mjmpm/validation.json)。当前已导出实验性 `newton.solvers.SolverMJMPM`，提供单轮代理双向反馈；本文中 P2/P3 的同一步内迭代与完整关节响应仍是待实现目标。参考后端的 30 个文件已迁入独立目录，原共享求解器源码保持不变。

## 1. 目标与边界

目标场景为机械臂、夹爪和灵巧手操作沙土、弹性体及弹塑性材料。材料反力必须能影响机器人运动，并在多指接触、高刚度或轻连杆条件下具有可量化的稳定性。

用户确认的架构约束：

- MuJoCo 求解的是完整 articulation，包含其连杆的受约束运动；“只有关节走 MuJoCo”不能理解为连杆再交给 MPM 独立积分。
- 不属于选定 articulation 的自由刚体全部由 MPM 侧积分，即使 Newton 用 free joint 表示该刚体，也不能因此分配给 MuJoCo。
- 软体和材料全部由 MPM 侧负责，不通过隐藏的 VBD/XPBD 后端代算。薄壳/布料等额外离散模型的支持需单独设计和验证，不能因为所有权归 MPM 就声称已经支持。
- 求解器实现完整放在独立目录，包含私有 MuJoCo 适配、MPM、刚体、碰撞和耦合代码，不以共享求解器或 Coupler 的组合包装作为最终交付。

分三个层次交付，不把它们混称为统一隐式求解：

1. **独立代理耦合**：迁入必要实现，建立 MPM 侧刚体动力学和双向反馈，形成可复现基线。
2. **同一步内迭代耦合**：机器人和材料从同一物理步初状态反复求解，协调接触运动与反力，降低滞后误差。
3. **关节响应参与接触迭代**：将关节系统的接触响应算子接入 MPM 内层求解，保留接触点之间通过关节链产生的关联。

首版不包含布料/VBD/MPM 三域耦合、任意跨求解器关节、断裂拓扑更新或可微求解。流体与不同塑性模型在基本接触接口通过验证后逐项扩展。首版不承诺所有材料模型和机器人控制设置下的无条件稳定性。

- 双向模式给连杆代理设置有效惯量，并默认按代理动量变化提取反馈。

- 技术总览同时保留早期单向架构描述；迁移时以固定提交的实际双向代码与测试为准。

### 2.2 独立代码边界

建议结构如下，具体拆分随实现调整：

```text
newton/_src/solvers/mjmpm/
    solver_mjmpm.py       # 独立入口与步进
    ownership.py         # 完整关节树和环境所有权
    solver_dispatch.py   # 无关节时仅执行 MPM 侧
    mujoco/              # 私有 MuJoCo 适配与关节响应
    mpm/                 # 私有材料、网格和流变求解
    rigid/               # 环境刚体积分、惯性响应和刚体接触
    collision/           # 私有接触构建和几何更新
    coupling/            # 私有状态同步、迭代和冲量反馈
```

- Newton 的 `Model`、`State`、`Control`、`Contacts`、核心数学/几何数据合同及 Warp、MuJoCo、MuJoCo Warp 等基础依赖可继续使用；代码独立不要求重写第三方引擎。
- 最终执行路径不实例化或继承共享 `SolverMuJoCo`、`SolverImplicitMPM`、`SolverCoupledProxy` 或其他共享求解器，也不依赖 MJVBD v2 的私有模块。
- 必要算法及 kernel 迁入本目录并保留来源、许可证和基线版本；逐项审计传递依赖，避免通过私有文件再次调用共享求解实现。
- 共享求解器只用于外部基线/测试对照。新增耦合、材料或碰撞优化全部在私有边界内完成，不修改共享求解器行为。
- 代码私有化意味着需要自行维护同步和回归；不能把仅有一个独立入口文件视为完成隔离。

现有有效质量/惯量估计不能等同于完整关节链响应。现有碰撞体响应也不能自动保证多个连杆遵守同一套关节约束。

MPM 已提供网格接触冲量，应直接用它累计反作用力和力矩，不照搬 VBD 的代理动量差提取方式。

现有有限质量碰撞体响应是刚体—材料交互基础，不等于已有完整的 MPM 侧环境刚体求解器。自由刚体积分、刚体—刚体接触、堆叠和静态环境接触必须在本计划中单独实现并验证。

## 3. 物理与状态合同

### 3.1 自由度与接触所有权

- MuJoCo 唯一拥有选定 articulation 的广义坐标、广义速度和所属连杆的真实动态状态。
- 私有 MPM 侧唯一拥有其余自由刚体的位置、姿态、速度和角速度，以及软体/材料粒子和材料历史变量。
- 环境刚体保留严格刚体表示及质量、惯量，由 MPM 侧刚体模块积分，并在该侧协调刚体与材料接触；不靠把材料刚度调大来冒充刚体，也不把刚体偷偷交给 MuJoCo。
- 选择 articulation 时必须保留完整关节树；固定基座、自由基座分别覆盖。
- 机器人—材料、环境刚体—材料、机器人—环境刚体、环境刚体—环境刚体及环境刚体—静态环境接触由 MPM 侧负责；涉及机器人连杆的冲量反馈给 MuJoCo。
- 机器人自碰撞、机器人—静态环境接触由 MuJoCo 负责，并在强耦合阶段与 MPM 侧接触协调。
- 材料—静态环境接触由 MPM 负责；静态几何可共享，接触对不能重复求解。
- 运动学模式可驱动材料，但不能宣称机器人具有动态反作用。

### 3.2 冲量与状态提交

- 明确世界坐标系、空间向量分量顺序、质心力矩与反作用符号。
- 对接触冲量 `p_i`，刚体反馈为 `F = sum(p_i) / dt`、`tau = sum((x_i - c) × p_i) / dt`。
- 区分外层物理步、MuJoCo 子步、材料迭代和耦合迭代，所有换算使用对应时间区间。
- 收敛后的接触冲量在两域中各作用一次，不同时通过速度修正和重复外力输入施加。
- 外部控制与外力在一次物理步的重算中固定；需要状态相关控制时单独定义其离散方式。

### 3.3 重算与历史状态

- 每轮耦合迭代从同一物理步初状态开始，只有接口迭代变量按约定延续。
- 审计环境刚体位姿/速度、粒子位置/速度、形变、塑性历史，以及碰撞体历史位姿、网格缓存、应力和接触 warm-start。
- 每次试探求解使用独立可恢复状态；最终只提交一次材料历史和机器人状态。
- warm-start 必须在接触失效、网格重建和环境 reset 后正确失效或重映射。
- 静态/运动学外界可施加外部冲量；守恒测试须把这些边界贡献单独记账。

4. 实现环境刚体平动/转动积分、刚体接触与刚体—材料交互；统一处理内部状态分发/回收、reset、冲量提取和反馈，示例只负责场景与控制。

## 6. 阶段 P2：同一步内迭代双向耦合

目标：在当前物理时间区间协调运动和反力，不将迭代次数变成额外物理时间。

初始方案：

1. 保存物理步初状态，以已有接口冲量作为初始猜测。
2. 用当前接口猜测重算 MuJoCo，得到本区间连杆运动预测。
3. 从步初环境刚体和材料状态重算 MPM 侧，提取新的接触冲量与接触运动。
4. 计算冲量残差和接触相对速度残差，进行固定松弛或经验证的 Aitken 更新。
5. 达到收敛条件或迭代预算后，以明确规则生成两域最终一致的状态并提交一次。

实施前需确定：lagged/staggered 位姿采样、碰撞几何是否及何时重建、MPM 速度回退项、两域最终使用的冲量一致性。最后一次 MPM 新冲量不能未经核对就搭配使用上一猜测推进出的 MuJoCo 状态。

收敛诊断同时包括绝对与相对残差，避免静止接触时归一化失效。达到迭代上限未收敛时必须暴露状态；CPU 可提前退出，Graph 路径可采用固定轮数与设备端收敛掩码。

验收：同一步内反力对机器人产生作用；增加迭代使接口不一致下降；改变迭代次数不重复累积塑性历史；相比单轮基线量化滞后和振荡改善。

## 7. 阶段 P3：关节响应接入 MPM 内层

### 7.1 接入位置

迁入后的私有 `build_rigidity_operator()` 构造碰撞体自由度到接触节点的映射与惯性响应，私有 `apply_rigidity_operator()` 在接触迭代中应用速度修正。

扩展时保留独立刚体路径，并为 articulation 增加可替换的响应算子。基本惯性形式为：

```text
广义冲量       delta_p_q = J_c^T delta_p_c
广义速度变化   solve M(q) delta_qd = delta_p_q
接触速度变化   delta_v_c = J_c delta_qd
接触响应       W_c = J_c M(q)^-1 J_c^T
```

这是待实现的数学接口，实际实现还须匹配 MPM 的网格权重、体素缩放、符号与接触变量定义。它不是接上上述公式便已完成全部约束耦合。

### 7.2 实现顺序

1. 固定位姿下验证接触 Jacobian、转置映射和质量矩阵求解，首个夹具只用小型关节链。
2. 优先采用矩阵自由算子，避免为大量 MPM 接触节点形成稠密 `W_c`；小模型显式矩阵只作参考。
3. 验证同一关节链不同接触点的交叉响应，不能退化为逐连杆独立有效质量。
4. 先处理仅惯性的线性化响应，再定义 armature、被动阻尼、驱动及其力矩饱和的贡献。
5. 对关节限位、机器人自碰撞及桌面接触，设计约束投影响应或与 MuJoCo 约束求解的外层协调，避免使用无约束响应后再分别投影而破坏材料接触。
6. 接触/关节配置变化时更新线性化；明确重线性化条件和非线性外层迭代。
7. 通过共同冲量更新广义速度、环境刚体和材料状态，避免完成内层后再次施加相同反馈。

先实现 CPU 或小规模参考路径以校验算子，再建设设备端路径。若 GPU 后端不能提供所需质量求解/约束响应，则把该问题作为阶段门槛记录，不以独立代理质量近似冒充完整关节响应。

验收：两连杆交叉响应正确；固定基座/自由基座均满足预期；简单模型与直接小系统参考解一致；报告当前支持的驱动、约束和材料范围。

## 9. 验证与验收矩阵

| 场景 | 核心验证 |
| --- | --- |
| 无重力、无外边界的刚体与材料碰撞 | 线/角动量收支、反馈符号和冲量只施加一次 |
| 无 articulation 的自由刚体落体/旋转与堆叠 | 纯 MPM 侧动力学、惯量、刚体接触和不启动 MuJoCo |
| 关节夹爪抓环境刚体 | 刚体归 MPM、连杆归 MuJoCo、接触冲量双向传递 |
| 单关节连杆压弹性块 | 驱动力矩与材料反力平衡、稳态漂移 |
| 两连杆两接触点 | 关节链交叉响应及与小系统参考解的一致性 |
| 双指夹持并保持 | 接触振荡、滑移、释放行为和控制饱和影响 |
| 塑性加载/卸载 | 残余形变及迭代重算不重复累计历史 |
| 静态桌面与材料同时接触 | 接触所有权、约束协调和反力分配 |
| reset、Graph 与多 world | 历史恢复、执行等价、环境隔离 |

记录指标：最大/均方穿透、接口速度残差、冲量残差、平衡误差、振荡幅值、滑移、动量误差和每物理秒计算成本。能量评估必须计入驱动做功、重力势能、边界功及塑性/摩擦/阻尼耗散。

P0 按场景尺度、网格分辨率与参考解冻结数值阈值和测试步数；阈值在实现前记录，不通过增大阻尼、armature 或代理质量掩盖失败。研究阶段扫描时间步、网格尺寸、材料刚度、质量比与耦合轮数；CI 只保留最小、独立且有辨识力的组合。

新增 solver 专属测试放在 `newton/tests/mjmpm/`，优先复用现有耦合和 MPM 覆盖。每个阶段检查 CPU 参考正确性；GPU/Graph 的支持范围单独标明。

## 10. 风险与阶段门槛

| 风险 | 处理与继续条件 |
| --- | --- |
| 轻连杆与高刚度材料导致反馈振荡 | 用基线定量识别；P2/P3 必须以收敛和误差指标证明改进 |
| 塑性历史和 warm-start 无法正确恢复 | 先通过重算一致性测试，再开展 P2 |
| 完整质量/约束响应接口不可用 | 保留 P1/P2，单独实现必要后端接口后进入 P3 |
| 多点接触算子稠密化 | 优先矩阵自由，报告显存和接触数扩展性 |
| MuJoCo 与材料接触重复求解 | 在 P1 固定接触所有权，并用组合场景验证 |
| MPM 侧缺少完整环境刚体动力学 | P1 补齐积分与刚体接触；不得借用 MuJoCo 承担环境刚体 |
| 私有实现仍有共享求解器传递依赖 | 审计执行路径并迁入必要实现，基础数据合同与第三方依赖除外 |
| 私有副本与上游实现逐渐偏离 | 记录迁入版本，维持小场景数值对照，按需显式同步 |
| Graph 掩盖未收敛或容量变化 | 设备端诊断、显式容量合同、捕获前 warm-up |

P1 完成只说明专用代理双向求解器可用；P2 完成说明同一步内迭代协调已验证；P3 完成才可声称完整关节惯性响应参与材料接触迭代。只有进一步验证约束、驱动和非线性收敛后，才讨论整体隐式耦合的范围与保证。
