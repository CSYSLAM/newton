# MJMPM 跨场景求解器优化调查

日期：2026-10-25。场景：W1 米锅倒米、面包切割和茶壶倒水。设备：RTX 5060 Ti 8 GiB。此页记录未并入求解器的候选方案与下一轮验证方向；已保留的改动见[优化索引](OPTIMIZATIONS.md)。

## 粒子到网格积分原型：未保留

现有 APIC 路径分别积分基础动量、APIC 动量和网格质量。原型使用四分量 FEM 场把三项并入一次积分：米锅夹持阶段速度/质量装配约 `3.73 → 2.32 ms/帧`，倒米阶段约 `0.95 → 0.63 ms/帧`。米锅、面包和茶壶初始状态的网格逆质量与速度最大差异在 `1e-8` 至 `1e-7` 量级，三个完整示例也通过了各自的验收。

但四个小场景回归失败：CPU 私有 MPM 与参考实现的材料历史超出精度阈值，低空气阻尼下粒子跨网格平面的用例在第 5 步产生非有限状态。一次积分把 APIC 项提前与基础动量相加，确实改变了累加顺序；这可能是误差增长的来源，但尚未单独证明。初始输入接近不足以保证非线性多步结果稳定，因此该原型已撤回。

保留 APIC 原积分顺序、仅合并基础动量与质量的两次积分原型通过上述四项回归。米锅夹持速度/质量装配约 `3.73 → 3.10 ms/帧`，但切面包单组完整运行的 warm 物理帧均值 `34.01 → 35.85 ms`，没有稳定的端到端收益。试图用跨步长数组视图消除中间复制核又使 CPU 回归失败。两种原型均已撤回；求解器源码保持提交 `9be2723b` 的路径。

后续又试了四分量 FEM 场的双次积分：第一次同时写基础动量与质量，第二次按原有顺序加入 APIC 动量，因而不需要额外复制核。四项 CPU 材料回归、B2/B3 单步运行，以及米锅、面包、茶壶三个完整示例验收都通过。米锅同配置分析窗口中，夹持阶段速度/质量装配 `3.71 → 3.03 ms/帧`，但整帧中位数 `35.30 → 35.56 ms`；倒米阶段装配 `0.94 → 0.83 ms/帧`，整帧 `33.67 → 33.05 ms`。茶壶 GL 离屏 900 帧单组对照为原型 `29.8 FPS`、碗内 `2566/2831`，原路径 `30.2 FPS`、碗内 `2558/2831`。收益没有稳定穿透到整帧，原型已撤回。单组计时不足以证明微小差异的方向；确定的结论是装配阶段的工作减少了。

## 可重建稀疏网格的进一步剖面

茶壶场景使用 Warp 的可重建 `Nanogrid`。网格已经由活跃粒子的位置生成，理论上可以用设备端有效体素计数直接标记活跃单元，省掉再次遍历粒子的查询。该原型在初始位置和两次平移后的分区索引与原路径逐元素相同，但标记阶段仅从约 `0.057` 降到 `0.041 ms/帧`，两段完整帧对照没有稳定收益，故已撤回。

随后对茶壶 500–539 帧倒水和 780–819 帧静置窗口拆分分箱阶段。两个窗口结果接近：`_particles_to_cells` 分别约 `3.84/3.79 ms/帧`，其中 `Nanogrid.rebuild` 约 `3.57/3.51 ms/帧`；粒子活跃掩码约 `0.028/0.027 ms/帧`，活跃分区约 `0.056/0.057 ms/帧`，`PicQuadrature` 构造约 `0.137 ms/帧`。嵌套事件将体素和节点网格的 `Volume.rebuild` 合计计为约 `2.32/2.28 ms/帧`，拓扑刷新约 `2.24/2.20 ms/帧`；这些嵌套区域不能与外层求和。可重建体素及其拓扑才是主要目标。

若继续优化稀疏路径，需在 CUDA Graph 中用设备端条件判断活跃体素集合是否变化，或改进活跃体素与节点拓扑的构建算法。只比较活跃体素数量不够：粒子跨单元时数量可以不变，但单元坐标已变。缓存还需覆盖停用粒子、多 world 打包、容量溢出和空间分区失效。现有 Warp 1.18.0 Python 接口没有在该路径使用的条件 Graph 节点；加入每步主机读回会抵消并行收益。因此本轮没有修改生产稀疏网格路径。

## 下一轮值得验证的通用方向

1. **确定性粒子到网格 gather。** 复用 PIC 分箱或邻接关系，让每个网格节点一次读取质量、基础动量和 APIC 动量，但按参考路径保留各项的累加语义与空节点处理。先做 Q1/APIC 专用实现，其余基保持原路径。米锅给出的可见机会约为准备阶段的 0.6–1.4 ms/帧；这段工作与刚体接触重叠，不能直接换算成整帧收益。必须先通过 CPU 参考、多步低阻尼、CUDA Graph 和三个完整场景，再做交替多组计时。
2. **减少活跃网格分箱与空间重建。** 茶壶倒水的分箱 3.6 ms、空间重建 1.8 ms 提示可研究增量更新或在活跃单元集合不变时复用分区。米锅分箱只有约 0.27 ms，收益依赖粒子分布，不能宣称所有场景都会获益。CUDA Graph 内的容量、粒子停用、网格改变和跨 world 索引都需要明确的失效条件。
3. **降低彩色 GS 的全局同步与启动开销。** 面包切割的 18.2 ms 迭代区是主要目标。可研究具备全网格同步的常驻 CUDA 核，保持颜色顺序与每次局部更新；单块融合版本已测得更慢，单纯换 GS-SoA 也没有收益。实现前应在相同冻结输入上测每次迭代的核启动、内存流量和占用率，再验证大、小色块及不同应变基。
4. **碰撞阶段的通用预筛选。** 茶壶和米锅分别约 9.3 和 5.2 ms，值得分解 broad phase、网格窄相和接触规约。先证明同一输入的接触集合、顺序和冲量不变；面包场景的环境碰撞成本并非主要项，因此这项不宜用面包 FPS 作为唯一验收。

目前没有一个经过三场景完整验证、同时带来稳定整帧增益的新通用求解器改动。下一轮优先做第一项的冻结输入等价性与第二项的阶段细分，不调整迭代次数、子步数或场景粒子数量来代替求解器优化。

## 2026-10-26: accepted mesh SDF group culling

The collision follow-up found a general mesh SDF narrow-phase optimization. Spatial edge traversal plus conservative 128-edge group culling reduced the teapot mesh contact kernel from 8.01 to 5.12 ms and the physical frame from 27.82 to 24.76 ms in frames 500-539. The original edge array and contact IDs remain intact. A frozen pose produced 48 bitwise-identical contacts, and the full teapot, rice cooker, bread cutting, and generic CUDA mesh SDF tests passed. See [the experiment record](EDGE_GROUP_CULLING.md). This supersedes the earlier conclusion on this page that no general improvement had been retained.
