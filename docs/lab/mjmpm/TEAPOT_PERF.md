# W1 倒水场景与 MJMPM 接触复用

记录日期：2026-10-25。分支：`feature/mjmpm-two-way-grasp`，实现提交：`9be2723b`。设备：RTX 5060 Ti 8 GiB，Warp 1.18.0。

## 保留的求解器改动

倒水示例使用 `rigid_material_coupling="constrained"`。每个子步先求解刚体接触，材料求解后再求解当前载荷下的接触反力。两次求解之间刚体位置和接触对不变，材料只改变速度。第二次求解因此复用第一次的刚体接触准备、受接触影响的连杆响应、接触压缩索引和接触空间 Delassus 矩阵；速度相关量仍重新读取，迭代次数不变。

第一次求解保存的初始接触冲量会在第二次求解前恢复，保持原有的 previous-step warm start。复用只用于满足 CUDA 接触空间、顺序 GS、局部 cooperative 桶和 constrained material 条件的反力恢复路径；其他路径继续准备自己的接触数据。接触空间原有的数值检查与参考求解回退仍运行。

此前[米锅性能记录](RICE_COOKER_PERF.md)第 2.8 节回退过一次更一般的接触准备复用：三组交替对照的典型帧时间没有稳定收益。当前实现额外复用接触空间矩阵，且应用范围更窄。两次实验的性能结论不可合并。

## 倒水场景测量

完整回放为 900 帧、15 秒模拟时间，默认每帧 4 子步、每次 60 遍刚体接触迭代、15 次 MPM 迭代，使用 2,831 个可见水粒子。以下是 RTX 5060 Ti 上的单组对照；FPS 为完整示例循环吞吐，不是纯 GPU 求解器计时。关闭复用仅用于诊断，没有新增公开运行参数。

场景直接绘制 MPM 粒子，没有逐帧重建水面。碗内粒子保持活跃；只有离开模拟工作区的粒子会被停用，末帧的停用数为 1。这个显示选择与接触复用是不同层次的改动。

| 模式 | 复用 | FPS | 接触压缩/矩阵构建次数 | 末帧碗中水粒子 |
| --- | --- | ---: | ---: | ---: |
| 无渲染 viewer | 开 | 37.7 | 3,600 | 2,613 / 2,831 |
| 无渲染 viewer | 关 | 36.8 | 7,200 | 2,554 / 2,831 |
| GL 离屏渲染 | 开 | 30.2 | 3,600 | 2,625 / 2,831 |

接触准备次数减半是确定的工作量变化；0.9 FPS 的无渲染差异只有一组对照，不能作为跨场景或稳定的加速比。GL 回放超过此前 25 FPS 目标。末帧截图确认壶留在夹爪中、碗内有水；自动检查还要求壶柄与右手 TCP 距离不超过 0.10 m、至少 85% 的水在碗内，并检查倒水结束后水没有大量离开碗。

五项相关测试通过，包括完整倒水示例、受载托盘、重材料上的轻箱、融合关节迁移率和标量柔度对照。新增抓握检查做过反例验证：人为将壶移离夹爪 0.30 m 时，旧检查通过，新检查报错。仓库级 `uvx pre-commit run -a` 通过。

## 本轮未保留的方案

- `rigid_material_coupling="lagged"` 在轻壶与水的载荷下可能使壶脱离夹爪，场景继续使用 `constrained`。
- 降低刚体迭代、MPM 迭代或每帧子步数不是本轮求解器提速方案；一些较低配置破坏倒水结果。
- 更小的接触空间容量、提前结束接触空间扫描、GS SoA/批量变体、Jacobi 和不同接触基在本场景没有同时得到稳定的速度与物理质量收益，因此没有并入本次提交。
- 临时对照有轨迹差异，其中一次关闭复用的 GL 运行大量漏水；无渲染对照和保留路径的完整测试均通过。表中的单组 FPS 应视作局部证据，接触复用尚缺跨场景、交替多次的稳定收益测量。

重现正常回放：

```powershell
uv run --extra examples -m newton.examples mjmpm_teapot_fill --viewer gl --headless --num-frames 900 --report-fps
uv run --extra dev -m newton.tests -k mjmpm_teapot_fill
```
